## 1. Мета й вимоги користувача
- **Вкладка «Клавіші»** (ідея користувача, зроблено в GK): графічна клавіатура й миша з поточними клавішами гри й модів (з `options.txt`), конфлікти, непризначені важливі дії, групування за категоріями або модами, моди — посиланнями; оновлюється при зміні клавіш у грі (`start.bat` → 2) або завантаженням свого options.txt у браузері. Клавіатура користувача — **Hator Skyfall TKL PRO (ANSI TKL 87, без цифрового блока)**. Специфікація й аналіз — `design/KEYBINDS.md`.
- Інтерактивний сайт-путівник по ATM11 (новий світ користувача): **дорожня карта** прогресу (етапи × групи модів, синергії), **довідник модів** з класами-бейджами, **гілки** (магія, техніка, виміри, боси) зі схемами, **квести** українською, позначки «зроблено».
- Мета гри: не прогавити цікаві механіки й не застрягнути в грінді — що з чим поєднувати в кожен момент.
- **Спойлери — так, але згорнуті** (боси, ендгейм, ATM Star — `spoiler: true` / компонент spoiler).
- Темний «ігровий» стиль. Модульна архітектура (за зразком pon-app користувача: ES-модулі без збирача, `// @ts-check`, `types.d.ts`, DOCUMENTATION/CHANGELOG, `.agent/workflows`). Файли — до ~300 рядків.
- Публікація: користувач викладе в GitHub і ввімкне **GitHub Pages з теки `docs/`**. Тому всі шляхи відносні, бібліотеки локальні (`docs/vendor`).
- Схеми: **ELK.js + власний SVG** — дорожня карта (дерево розвитку v2); **Cytoscape.js** — глави квестів і мапа синергій; **jsPlumb** — малі схеми в гілках.
- Бере факти з: jar модів (метадані, книги), квестів FTB (`config/ftbquests`), нашого перекладу (`ua_work/review/effective.tsv`, `ua_work/books_tr`, `books_gm`), GLOSSARY. Назви предметів — **як у грі українською** (effective.tsv), терміни — за `ua_work/GLOSSARY.md`.
- **Користувач ATM11 ще не грав** (колись грав ATM 6/7) і покладається на реверс-інжиніринг збірки: факти брати з файлів збірки, а не «з пам'яті». Порядок джерел: KubeJS (`minecraft/kubejs/server_scripts` — змінені/вимкнені рецепти, умови `Platform.isLoaded`) → конфіги (`minecraft/config/*.toml` — радіуси, місткості, вимкнені функції) → типові клавіші (`minecraft/options.txt`) → jar (`tools/jarq.py`: lang-підказки, рецепти, предмети) → квести й книги → desc_en. `verify: true` («⚑ Чернетка») — лише те, що не вдалося підтвердити даними; етапи (`stage`) — за вартістю рецептів (`jarq.py uses`).

## 3. Схема ручного вмісту (content/)
**content/mods/<група>.json** — `{ "<modid>": {…}, … }` (ключі `_…` — коментарі):
- `cls`: ["magic", "exploration"] — класи з classes.json, перший — головний; **давати ВСІ категорії, до яких мод належить** (рішення користувача), а не одну-дві
- `role`: content | addon | qol | library | perf;  `parent`: "ae2" (для доповнень)
- `uk`: 1–2 речення — що це і навіщо гравцю (головне поле!)
- `what`: ["додає …", …] — ключові можливості (3–6 пунктів);  `stage`: ["s2", "s3"] — коли актуальний
- `synergy`: [{"mod": "ae2", "why": "…"}] — з чим поєднувати;  `tips`: ["…"];  `spoiler`: "…" (згорнуто)
- `chapter`: файл глави квестів;  `book`: назва книги в грі;  `branch`: id гілки
Мод без запису показується з автокласом (пунктирний бейдж) — `build_data.py` визначає library/perf/qol евристикою.
- `verify`: true — «⚑ Чернетка» (не підтверджено даними збірки) на сторінці мода;  `parent` — сторінка батька сама показує список доповнень
- `icons`: ["ae2:controller", …] — ключові предмети мода (іконки);  `features`: ["boss", …] — ПОВНІСТЮ замінює автовизначені піктограми; **автовизначення неточне — для кожного описаного мода перевіряти й записувати `features` явно** (виміри — dimension/*.json; боси — тег c:bosses; данжі — будь-яка структура; біоми; руди — placed_feature з ore; істоти — ≥2 яєць виклику) (dimension | boss | dungeon | biome | ores | mobs);  `dims`: [{id, name}] — замінює автоназви вимірів
**roadmap.json** (дерево v2, design/ROADMAP_V2.md) — `groups`: [{id, title, cls, mods[], desc?}] (сузір'я); вузол: `id, stage, lane, group, trunk?, star?, title, icons[], mods[], features?, chapter?, spoiler?, verify?, text, done_by: {quests?: [hexId], advancements?: [id], items?: [id]}`; ребро: `from, to, kind` (req | syn | opt), `label?`.
  - `trunk: true` — стовбур (квести «Розділ 1/2»), рівна вертикаль посередині; `star: true` — значок ★ «потрібно для ATM Star» замість довгої лінії.
  - `lane` — колір і бік дерева (ліворуч: storage, logistics, farming, resources, gear, exploration — `LEFT_LANES` в elk-layout.js; решта праворуч).
  - Стан «доступно» рахується з ребер `req` (усі виконано), без них — хоч один попередник. Ребра лише згори вниз (етап from ≤ to — build_data перевіряє).
  - Позиції рахує ELK у браузері; налагодження: `#/roadmap?elk.<параметр>=<значення>` (напр. `elk.spacing.nodeNode=50`).
**Іконки** — будь-яке поле `icons` / `icon` з ID предметів; після додавання: `tools/extract_icons.py` → `tools/build_data.py` (попередить, якщо іконки немає). Шукати ID: `extract_icons.py --find "occultism:.*chalk"`.
**branches/<id>.json** — `title, icon, cls, mods[], chapter, book, enter (етап), summary, gives[], steps[{id, x, y, title, text, spoiler?}], links[[from, to]], verify`. x, y — клітинки сітки 230×110.
**keys.json** (вкладка «Клавіші», design/KEYBINDS.md) — `cats`, `ctxs`, `rules`: правила згори вниз **каскадом** (пізніше уточнює раннє), збіг — `re` (regex за id дії) і/або `ns` (повний збіг простору імен). Поля: `cat`, `ctx` (game | held | vehicle | gui | debug), `scr` (для gui: `c:*` — будь-яке вікно з інвентарем, `c:<ім'я>`, `quests`, `map`, `jei-recipes`…), `nc` (не конфліктує: модифікатор/дія над елементом), `soft` (умовна — конфлікт лише «можливий»), `important`, `note`, `mod`/`name` (власник і назва, якщо їх немає в перекладі); `null` — скинути поле. `plan`: [{id, to («Ctrl+G» | «F8» | «none»), why}] — план перепризначень (build перевіряє, що не створює конфлікту; `raw/keys_plan.txt` — рядки для options.txt). Схема `docs/data/keys.json` і правила конфлікту — DOCUMENTATION.md. Пари дій одного мода не конфліктують; «з предметом» × «у світі» — лише можливий конфлікт (рішення користувача).
Перевірка: `build_data.py` попереджає про невідомі моди, класи, етапи, вузли, дії без категорії/контексту, правила без збігів, зайняті поради (усе має бути 0).

## 4. Рецепти
- **Зібрати дані після правок content/**: `python3 -I tools/build_data.py`
- **Нові іконки** (додано ID у content/): `python3 -I tools/extract_icons.py && python3 -I tools/build_data.py`. Ванільні текстури — з клієнтського jar (common.CLIENT_JARS: `%APPDATA%/PrismLauncher/libraries/com/mojang/minecraft/<версія>/…-client.jar`; у сесії Claude — тека `~/mnt/<версія>`, доступ запитати device_request_folder_access). Моделі Geckolib (`.geo.json`: машини Oritech, піч Theurgy…) малюються автоматично. Не вийшло — `raw/icons_missing.txt` → заміна в `content/icons_override.json`: `item` (інший предмет), `cube` (текстури граней), `models` (+ `fit`), `boxes` (коробки з текстури-розгортки істоти: скрині, черепи, реактор Powah), `texture` (плоска). Вікі Minecraft з хмари недоступна — усе з jar гри й модів.
- **Оновлення збірки ATM11** (нові jar / квести): `python3 -I tools/extract_mods.py && python3 -I tools/extract_quests.py && python3 -I tools/extract_icons.py && python3 -I tools/build_data.py` (extract_quests бере назви з `ua_work/review/effective.tsv` — спершу оновити переклад: `ua_work/review/effective.py`).
- **Оновлення клавіш** (користувач перепризначив клавіші в грі): `python3 -I tools/extract_keys.py && python3 -I tools/build_data.py` (у Windows — `start.bat` → «2» або `start.bat keys`). Нова дія мода без правила → попередження «без категорії» — додати правило в `content/keys.json`.
- **Оновлення прогресу із сейву** (після гри, коли світ збережено виходом у меню або автозбереженням): `python3 -I tools/extract_progress.py [--world "Назва"] && python3 -I tools/build_data.py` (у Windows — `start.bat` → «3» або `start.bat save`).
- **Локальний перегляд**: `start.bat` (Windows; меню 1 — сайт, 2 — оновити клавіші; справжній Python → http.server, інакше — `tools/serve.ps1` на PowerShell; у користувача Python немає — лише заглушка Microsoft Store, тому оновлення даних з ПК потребує встановленого Python 3; start.bat — лише ASCII, кирилиця в UTF-8 ламає cmd) → http://localhost:8811 або VS Code Live Server на теці `docs`. Подвійний клік по index.html НЕ працює (ES-модулі й fetch потребують сервера).
- **Перевірка в браузері з хмари (Claude)**: на пристрої `tar czf raw/tmp/docs.tgz docs` → device_stage_files → у контейнері розпакувати, `python3 -m http.server 8811`, Playwright (`/opt/npm-tools/node_modules/playwright`, Chromium уже є) → скриншоти + `pageerror` = 0.
- **Пастка device_commit_files**: копіює з кешу за шляхом у `/mnt/user-data/outputs` — повторний коміт з ТОГО САМОГО шляху може записати стару версію. - **Уніфікація піктограм та узгодження `cls` ↔ `features` (`components/feat.js`, `badge.js`)**:
  - Усі піктограми можливостей (`FEATS`: `dimension`, `boss`, `dungeon`, `biome`, `ores`, `mobs`) та піктограми 14 класів модів (`CLS_ICONS`: `tech`…`perf`) малюються єдиним контурним векторним SVG-набором (`viewBox="0 0 24 24"`, `stroke-width: 1.9`, колір через `--fc` / `--c`) без системних емодзі, які відрізняються між шрифтами й ОС.
